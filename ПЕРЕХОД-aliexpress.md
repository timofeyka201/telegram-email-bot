# Переход витрины на AliExpress

Витрина больше не стоит на Etsy: товары берутся из партнёрского API AliExpress
через [AE Platform](https://aeplatform.ru). Здесь — как это устроено, что нужно
сделать в кабинете и на сервере, и что ещё предстоит проверить на живом ключе.

## Как устроено

Схема та же, что доказала работоспособность на Etsy, и по той же причине: у
платформы есть лимиты, а приложение не должно тратить их на каждый свайп.

```
AE Platform ──► импортёр по расписанию ──► снапшот на диске ──► лента, карточка, свайпы
                (scripts/build-catalog-ae.mjs)   (catalog.json)
```

* **Импортёр** раз в сутки обходит продуктовые фиды курсором `fromLastId` и
  складывает товары в `catalog.json`. Ни один свайп не стоит ни одного запроса
  к API.
* **Журнал бюджета** `ae-budget.json` лежит рядом со снапшотом: счётчик
  запросов за сутки, номер фида и курсор. Счётчик сбрасывается со сменой суток,
  **место в обходе — нет**: иначе каждую ночь импортёр начинал бы сначала.
* **Остановка впустую** — после 50 страниц подряд без новых карточек прогон
  заканчивается сам: фиды обойдены, тратить остаток бюджета не на что.
* **Картинки** скачиваются на свой сервер (`npm run catalog:images`) и
  раздаются nginx, минуя Node.
* **Партнёрская ссылка** создаётся лениво — на первый переход в магазин, а не
  на весь каталог: на 60 тысяч товаров это были бы 60 тысяч запросов ради
  карточек, которые никто не откроет. Созданная ссылка кладётся в
  `ae-creatives.json` навсегда.

### Токен

Токен живёт полчаса, и **выдача нового убивает прежний**. Поэтому он общий:
лежит в `ae-token.json` (права `600`) и переиспользуется и приложением, и
импортёром. Если токен всё же выбили, запрос повторяется с новым — это штатная
ситуация, а не сбой.

Схему заголовка документация не называет (`token_type` приходит как `jwt`),
поэтому клиент подбирает её сам — `Bearer`, `jwt`, без префикса — и запоминает
сработавшую. Если знаете точно, задайте `AE_AUTH_SCHEME`.

## Что нужно в кабинете AE Platform

1. **Client credentials** — Мой профиль → Client credentials. Нужны права:
   * «Доступ к продуктовым фидам» — без них импортёр не увидит ни одного фида;
   * «Проверка ссылки на аффилиатность» — для сведений о товаре;
   * создание креативов — для партнёрских ссылок.
2. **Площадка** — Инструменты → Площадки: добавьте `swipers.ru` и дождитесь
   активации. Без площадки креатив не создаётся, но её идентификатор искать не
   нужно: приложение спрашивает список активных площадок у самой платформы и
   берёт первую. `AE_PLACEMENT_ID` нужен, только если площадок несколько и
   нужна конкретная. Тем же способом берётся и `AE_USER_ID` — он лежит внутри
   токена; задавать его в настройках не обязательно.
3. **Постбэк** — Инструменты → Постбэки, шаблон:

   ```
   https://swipers.ru/api/ae/postback?key=СЕКРЕТ&order_number=%{order_number}%&order_status=%{order_status}%&product_id=%{product_id}%&price=%{price}%&commission_user=%{commission_user}%&currency=%{currency}%&user_sub_id=%{user_sub_id}%
   ```

   Тот же `СЕКРЕТ` кладётся в `AE_POSTBACK_SECRET`. Без него адрес отвечает
   404 — он открыт в интернет, и писать в наш журнал кто угодно не должен.

## Что сделать на сервере

```bash
# 1. ключи и настройки
sudo -u swiper nano /home/swiper/.env.production
#   AE_CLIENT_ID=…
#   AE_CLIENT_SECRET=…
#   AE_USER_ID=…
#   AE_PLACEMENT_ID=…
#   AE_POSTBACK_SECRET=…

# 2. проверка связи: токен, список фидов, первая страница товаров
#    ENV_FILE нужен потому, что настройки лежат отдельно от кода и сами
#    в окружение команды не попадают
su - swiper -c 'cd ~/app && ENV_FILE=/home/swiper/.env.production node scripts/build-catalog-ae.mjs --check'

# 3. первый импорт (бюджет расходуется постепенно, за несколько ночей)
su - swiper -c 'cd ~/app && ENV_FILE=/home/swiper/.env.production node scripts/build-catalog-ae.mjs --file /var/lib/swiper/catalog.json'

# 4. картинки к себе
su - swiper -c 'cd ~/app && node scripts/cache-images.mjs --file /var/lib/swiper/catalog.json'
```

Ночной cron: те же две команды, импорт и картинки, в этом порядке.

## Проверка без живого ключа

Рядом лежит поддельная площадка `scripts/ae-fake.test.mjs`: отвечает в тех же
форматах, выбивает токен, умеет отдавать 401 и 429. На ней прогоняются и
импортёр, и приложение — ключ и лимиты настоящей площадки при этом не
тратятся.

```bash
node scripts/ae-fake.test.mjs &
AE_CLIENT_ID=1 AE_CLIENT_SECRET=2 \
AE_TOKEN_URL=http://127.0.0.1:3340/token AE_API_BASE=http://127.0.0.1:3340 \
node scripts/build-catalog-ae.mjs --check
```

## Что ещё предстоит уточнить на живом ключе

Документация не раскрывает часть деталей, поэтому они сделаны «терпимо» —
несколько вариантов имени поля, и первое подошедшее побеждает. После первого
`--check` на настоящем ключе станет видно, что приходит на самом деле.

* **Имена полей товара в фиде.** Разбор принимает `salePriceCents` / `price`,
  `productUrl` / `link`, `images` / `imageUrl` и так далее. `--check` печатает
  сырой ответ и то, как он лёг в карточку; `--dump raw.json` сохраняет первые
  двадцать товаров целиком.
* **Числовые лимиты.** Платформа их не публикует. Пока: 2000 запросов в сутки,
  четверть секунды между запросами, остановка при первом же 429.
* **Поиск `/products/search`** — «доступ по предварительному согласованию».
  Сейчас поиск идёт по снапшоту (`src/lib/search.ts`): по словам с учётом
  падежей и синонимов, с сортировкой по близости к запросу. На ста тысячах
  карточек первый запрос занимает доли секунды, следующие страницы того же
  запроса — миллисекунды, разобранные названия держатся в памяти (около
  пятидесяти мегабайт) и пересобираются при смене снапшота. Доступ к поиску
  площадки понадобится, только если захочется искать по всему AliExpress, а
  не по своей витрине.
* **Срок жизни данных.** У Etsy было ограничение на хранение снапшота. Есть ли
  такое здесь — в документации не сказано, стоит спросить у платформы.

## Что осталось от прежней витрины

Источники 1688, Wildberries и открытый демонстрационный каталог убраны из
реестра (`src/lib/providers/index.ts`), но их код остался в репозитории —
вернуть любой из них можно одной строкой. Офлайн-подборка осталась запасным
вариантом: если снапшота ещё нет, лента не пустует.

Импортёр Etsy (`scripts/build-catalog-etsy.mjs`) тоже остался. Он больше не
нужен витрине, но и не мешает — удалим, когда AliExpress отработает месяц.
