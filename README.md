# Свайпы 1688

Витрина товаров с 1688 с механикой Tinder: свайп вправо — нравится, влево — мимо,
вверх — сразу в корзину. Тап по карточке открывает подробности: галерея, описание,
характеристики, отзывы, оптовые цены и поставщик.

## Быстрый старт

```bash
npm install
npm run dev                       # http://localhost:3000
```

Ключи не нужны: без настройки лента едет с открытого каталога с настоящими
фотографиями. Чтобы включить 1688, скопируйте `.env.example` в `.env.local`
и впишите `BHAPI_TOKEN`.

## Источники данных

Все источники живут за одним интерфейсом `Provider` и отдают одинаковые
карточки, поэтому переключение не меняет ни UI, ни логику ленты.

| Источник | Ключ | Что даёт |
| --- | --- | --- |
| **Своя база** (`local`) | не нужен | `data/catalog.json` в репозитории — 1000 карточек. Ни от каких внешних API не зависит, поэтому не ловит ни лимитов, ни блокировок. **Источник по умолчанию.** |
| **1688 по токену** (`bhapi`) | `BHAPI_TOKEN` | Живой парсинг маркетплейса. Единственный по-настоящему безграничный источник: страницы выдачи идут, пока площадка их отдаёт. |
| **Wildberries** (`wb`) | не нужен | Живой публичный поиск маркетплейса. Работает с обычной машины, но **с серверов Vercel отвечает `429`** — маркетплейс режет запросы из дата-центров. Держим как опцию, не как основу. |
| **Открытый каталог** (`catalog`) | не нужен | [DummyJSON](https://dummyjson.com) — бесплатный REST без авторизации: ~194 товара с настоящими фото, отзывами и минимальной партией. Запасной вариант. |
| **Офлайн-подборка** (`demo`) | не нужен | 12 карточек внутри приложения. Нужна, когда внешней сети нет вовсе. |

`/api/feed` пробует запрошенный источник, а при отказе спускается по цепочке к
следующему готовому — поэтому лента не обрывается из-за одного недоступного API.

## Своя база товаров

Маркетплейсы отдают выдачу браузеру, но отказывают серверу: запрос из
дата-центра получает `429`. Поэтому лента больше не ходит в чужой API на каждом
свайпе — она читает собственную базу `data/catalog.json`, которая лежит рядом с
кодом и отдаётся постранично через `/api/feed`.

Отдельный бэкенд-сервис для этого не нужен: маршруты в `src/app/api/*` — это уже
бэкенд, Vercel разворачивает их как serverless-функции вместе с фронтендом.

### Чем наполнить

**Сразу после клонирования** база содержит 1000 синтетических карточек на
русском: 25 категорий, цены, рейтинги, отзывы, характеристики. Это не копии
чужих товаров — у них нет чужих фотографий и нет ссылок на несуществующие
страницы. Нужны, чтобы приложение работало из коробки.

```bash
npm run seed            # пересобрать синтетическую базу
```

**Настоящие товары** собирает импортёр. Запускать его нужно с обычной машины —
с серверного адреса маркетплейс ответит отказом:

```bash
npm run build:catalog                        # 1000 товаров Wildberries
node scripts/build-catalog.mjs --target=2000 # больше
node scripts/build-catalog.mjs --no-cards    # без описаний, быстрее
node scripts/build-catalog.mjs --queries="дрель,шуруповёрт,перфоратор"
```

Скрипт перебирает ~50 категорий, складывает результат в `data/catalog.json`
после каждой страницы (прервали — запустите снова, продолжит с того же места),
выдерживает паузы между запросами и отступает с увеличивающейся задержкой на
`429`. Дальше файл нужно закоммитить и задеплоить.

### Что делается с фотографиями

Файлы изображений **не скачиваются и не перезаливаются** — база хранит ссылки
на оригиналы, а браузер грузит их напрямую с CDN маркетплейса. Так репозиторий
не распухает на сотни мегабайт, и запрос за картинкой идёт с адреса
пользователя, а не из дата-центра — то есть мимо тех самых лимитов.

`src/components/Img.tsx` пробует три шага по очереди: прямая загрузка без
`Referer`, затем собственный прокси `/api/img`, затем заглушка. Одна неудачная
ссылка не оставляет карточку пустой.

## Почему лента бесконечна

Страница ленты возвращает непрозрачный курсор `смещение.круг`, и он **никогда не
бывает пустым**: дойдя до края конечного каталога, провайдер сам начинает новый
круг с другой перетасовкой (`seed + круг`) и помечает карточки суффиксом круга,
так что дубликатов по `id` в ленте не возникает. Клиент запрашивает следующую
страницу, как только впереди остаётся меньше восьми карточек, поэтому под пальцем
колода не заканчивается. Просмотренные карточки подрезаются, чтобы память и
`localStorage` не росли бесконечно.

Своя база из 1000 карточек выдаётся за 84 страницы, после чего начинается новый
круг с другой перетасовкой: прогон по курсору дал 1192 карточки подряд без
единого дубликата идентификаторов.

У Wildberries лента идёт ещё и вширь: без поискового запроса провайдер
перебирает по кругу список из 42 русских категорий, а внутри каждой листает
страницы выдачи. Прогон по курсору дал **5220 уникальных карточек за 174
страницы** без единого обрыва, дальше лента продолжается.

Для конечного каталога тот же прогон: 26 страниц, 302 карточки, 0 дублей,
переход на второй круг произошёл автоматически.

### Картинки Wildberries

В выдаче поиска ссылок на фото нет — их собирают из id товара, причём номер
CDN-корзины зависит от диапазона id. Диапазоны со временем сдвигаются, корзин
становится больше, а часть CDN не обслуживает `HEAD` — поэтому угадывать ссылку
заранее нельзя: один промах, и карточка навсегда остаётся без фото.

Вместо этого карточка получает ссылку вида `/api/img?wb=<id>&n=<номер>`, а
подбор происходит в момент запроса картинки: `src/lib/wb-basket.ts` перебирает
корзины пачками параллельно (начиная с подсказки по диапазону), пробует
несколько форматов пути и берёт первый ответивший, запрашивая один байт через
`Range` вместо `HEAD`. Найденная пара «корзина + формат» кэшируется на весь
диапазон, поэтому платится это один раз.

Если картинок не видно, ответ даёт `/api/diag`: там видно, отвечает ли поиск
Wildberries, какие корзины перебирались и какая ссылка в итоге выбрана.

Описание и характеристики тоже приходят не в выдаче, а в `card.json` на той же
CDN: их подтягивает `/api/item`, когда пользователь открывает карточку.

## Что умеет

**Главная — лента**
- Выбор источника данных прямо в панели подбора.
- Поиск по слову; для 1688 дополнительно режим «По ссылкам» (ссылки на товары
  или их ID списком — до 40 за раз, запросы идут параллельно по 5).
- Быстрые чипы с популярными категориями.
- Колода из трёх карточек с физикой перетаскивания, штампами решения и поворотом.
- Тап по левому/правому краю карточки листает фото, тап по центру открывает подробности.
- Клавиатура: `←` мимо, `→` нравится, `↑` в корзину, `Enter`/`Space` подробности, `Backspace` вернуть.
- Кнопка «вернуть карточку» отменяет последнее решение вместе со всеми его последствиями.
- Лента дозагружается сама и не заканчивается.

**Карточка товара**
- Галерея со снапом, миниатюрами и счётчиком.
- Цена в рублях и юанях, таблица оптовых порогов, варианты (SKU), минимальный заказ.
- Вкладки: описание, характеристики, отзывы (с фото покупателей).
- Блок поставщика, ссылка на оригинал на 1688.
- Если товар пришёл из выдачи поиска без описания и отзывов — они догружаются по ссылке.

**Избранное и корзина**
- Избранное — плитка с быстрым добавлением в корзину.
- Корзина считает цену по оптовому порогу для текущего количества и складывает
  товары из разных источников: итог в рублях, суммы по каждой валюте отдельно,
  курсы редактируются вручную.
- «Скопировать заказ» кладёт в буфер список с количествами, ценами и ссылками.

**Вовлечение**
- Дневная цель в 20 карточек с кольцом прогресса.
- Счётчик серии лайков подряд.
- Тактильная отдача на свайпах, тосты, экран «карточки закончились» с итогами сессии.
- Всё состояние (колода, позиция, избранное, корзина, статистика) переживает перезагрузку.

## Стек

Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · Framer Motion · Zustand.
Состояние — в `localStorage`, без базы и без авторизации: для MVP этого достаточно,
а добавить бэкенд можно, не трогая UI.

## Как устроена работа с парсером

```
data/catalog.json      собственная база товаров (её отдаёт /api/feed)
scripts/make-seed.mjs  генератор синтетической базы на 1000 карточек
scripts/build-catalog.mjs  импортёр настоящих товаров с маркетплейса
src/lib/providers/     источники ленты за общим интерфейсом
  local.ts             своя база: пагинация, поиск, закольцовывание
  types.ts             Provider, курсор, детерминированная перетасовка
  bhapi.ts             1688 по токену
  wildberries.ts       Wildberries: поиск, сборка ссылок на фото, card.json
  dummyjson.ts         открытый каталог (CATALOG_BASE переопределяет базу)
  demo.ts              офлайн-подборка
src/lib/bhapi.ts       клиент 1688: токен, таймауты, кэш, разбор ошибок
src/lib/normalize.ts   приведение произвольного JSON к модели Product
src/lib/feed.ts        загрузка следующей страницы (одна точка для UI)
src/lib/types.ts       модель данных
src/app/api/feed       POST: страница бесконечной ленты с курсором
src/app/api/parse      POST: разбор конкретных ссылок 1688
src/app/api/item       GET:  полная карточка по ссылке
src/app/api/img        прокси картинок (alicdn отдаёт их только со «своим» Referer)
src/app/api/placeholder  локальные SVG-заглушки вместо битых фото
src/app/api/health     список источников и их готовность
src/app/api/debug      сырой ответ парсера — для сверки схемы
```

Токен читается только на сервере и в браузер не уходит: фронт ходит в свои `/api/*`.

### Про эндпоинты

Подтверждён один эндпоинт — тот, что был в задании:

```
GET https://bhapi.ru/1688/api/v1/item/by-url?url=...
Header: X-API-Token: <токен>
```

На нём построен режим «По ссылкам» — он работает гарантированно.

Точный путь для поиска по ключевому слову в задании не назывался, поэтому
`search()` в `src/lib/bhapi.ts` перебирает пять правдоподобных вариантов
(`/item/search`, `/search`, `/items/search`, `/search/items`, `/item/by-keyword`)
и запоминает сработавший. Если у парсера поиск называется иначе или его нет,
режим «По слову» вернёт понятную ошибку и предложит вставить ссылки. Правится
это одной строкой в списке `SEARCH_CANDIDATES`.

### Про схему ответа

Точная структура JSON тоже не была зафиксирована, а из окружения разработки
`bhapi.ru` недоступен, поэтому нормализация в `normalize.ts` не привязана к
жёстким путям: она обходит JSON в ширину и выбирает первое правдоподобное
значение по смыслу ключа (`title|subject|name|...`, `images|imgs|pics|...`,
`price|priceRange|...`, `reviews|comments|feedback|...` и так далее). Это
переживает переименования полей и разные формы обёрток (`data`, `result`, `item`).

Чтобы свериться с реальной схемой и при желании ужать маппинг под конкретные поля:

```bash
curl 'http://localhost:3000/api/debug?path=/item/by-url&url=https://detail.1688.com/offer/123456789.html' | jq
```

## Деплой на Vercel

Проект лежит в корне репозитория, поэтому Root Directory менять не нужно, и
собирается без единой переменной окружения.

1. **Vercel → Add New → Project → Import Git Repository**, выбрать этот репозиторий.
2. Framework Preset определится как **Next.js**, остальные поля оставить как есть.
3. **Важно:** проверить, с какой ветки идёт production. По умолчанию Vercel берёт
   ветку по умолчанию репозитория — если приложение живёт в отдельной ветке,
   указать её в *Settings → Git → Production Branch* либо влить ветку в основную.
4. Deploy.

База едет в репозитории, поэтому деплой — это обычный git push: отдельную
базу данных, хранилище или второй сервис поднимать не нужно.

### Переменные окружения

Все необязательные — без них приложение работает на своей базе.

| Переменная | Зачем |
| --- | --- |
| `BHAPI_TOKEN` | включает источник 1688 |
| `BHAPI_BASE` | другой адрес парсера 1688 |
| `CATALOG_BASE` | зеркало открытого каталога |
| `WB_SEARCH_BASE`, `WB_BASKET_BASE` | зеркала Wildberries |
| `IMG_EXTRA_HOSTS` | дополнительные хосты картинок через запятую |
| `ENABLE_DEBUG=1` | открывает `/api/debug` в проде |

Добавлять их — *Settings → Environment Variables*, затем передеплоить.

### Что учтено для serverless

- Маршруты `/api/feed`, `/api/item`, `/api/parse` объявляют `maxDuration = 30`.
- Таймауты обращений к источникам — до 9 секунд, а перебор источников в
  `/api/feed` укладывается в бюджет 20 секунд, чтобы функция успела ответить
  даже когда первый источник висит.
- Кэши источников живут в памяти инстанса и не переживают его перезапуск: это
  не ломает ленту, просто первая карточка после холодного старта требует
  лишнего запроса к CDN.

## Ограничения MVP

- Нет авторизации и серверного хранилища: избранное и корзина живут в браузере.
- Корзина не оформляет заказ — она собирает список и отдаёт его в буфер обмена.
- Курсы валют задаются вручную, доставка и комиссии не считаются.
- Импортёр не забирает тексты отзывов: выдача маркетплейса их не содержит,
  карточка показывает рейтинг и количество.
- База обновляется запуском импортёра вручную: цены в карточках держатся на
  момент сборки, а не в реальном времени.
- Wildberries не отдаёт тексты отзывов в выдаче: карточка показывает рейтинг и
  их количество, но не сами отзывы.
- У открытого каталога 194 уникальных товара: лента не обрывается, но после
  этого числа карточек начинается новый круг в другом порядке.
